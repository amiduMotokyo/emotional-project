# 多模态情感项目协作

## 目的与适用范围

将本项目任务落实到正确的负责人目录，保持共享代码唯一、实验可追溯、论文与实际结果一致。此Skill扩展项目AGENTS.md中的工作规则，不替代用户当前指令或赛题要求。

本Skill随项目保存在 `.agents/skills/emotional-project-collaboration/`。从Skill目录向上三级可定位项目根目录，并结合AGENTS.md、A/B/C、docs确认；data可能尚未单独分发，不以其缺失否定项目身份。本Skill的引用文件相对于Skill目录，项目文件路径相对于确认后的项目根目录。不依赖任何成员的用户名、盘符或个人技能安装位置。

用户询问概念时直接回答；只有任务要求产出文件时才创建或修改文件。不要因为使用此Skill而自动启动训练、重建全部目录、重写总计划或创建额外报告。

## 开始任务

1. 读取当前项目AGENTS.md；首次参与协作或改变公共接口时读取 `docs/项目结构与协作约定.md`。
2. 依据用户目标判断模块和负责人，核查目标目录已有实现与文档，优先延续已有文件。用户指定负责人时尊重指定；若涉及其他成员维护的公共模块，保留原模块归属。
3. 只有安排工期、分配任务或改变里程碑时，读取 `docs/三天模块分工与论文写作计划.md`，不要把早期进度描述视为永久状态。
4. 根据任务选择下面的操作流程；只加载当前需要的参考文件。

## 模块与目录归属

| 模块 | 维护者与实现位置 | 主要产物 |
|---|---|---|
| M1：数据接口 | B/src/ | 读取、字段适配、批次与掩码 |
| M2：问题1特征处理 | A/src/ | 100条自生成特征、覆盖核查 |
| M3：时间映射与证据定位 | A/src/ | 文本区间、语音时段、视频帧映射 |
| M4：共用融合基线 | B/src/ | 三模态编码、融合、分类和回归 |
| M5：缺失鲁棒训练 | C/src/ | 连续缺失、训练策略、专项预测 |
| M6：模态贡献与解释 | B/src/ | 贡献量化、局部证据、解释卡 |
| M7：统一评估 | C/src/ | 指标、实验配置、消融汇总 |
| M8：统稿与打包 | A负责统稿，C负责打包 | docs/A/paper/与C/outputs/submission/ |

每位成员使用以下归档方式：

- `<负责人>/src/`：可复用实现；`configs/`：配置；`scripts/`：运行入口。
- `<负责人>/outputs/`：自生成特征、缓存、权重、原始日志及导出结果。
- `docs/<负责人>/requirements/`：需求理解、修改建议、任务拆解。
- `docs/<负责人>/research/`：文献、创新点、候选方法和对照设计。
- `docs/<负责人>/experiments/`：可阅读的实验记录、结果解释和失败分析。
- `docs/<负责人>/paper/`：本人论文正文与排版材料。
- 文档长期使用的配图放在对应文档目录的 `assets/`，通过相对链接引用；不只链接被忽略的临时输出。

`docs/`根目录仅放原始题目、总计划和全组约定。跨题不等于公共文档：C分析缺失方法仍放docs/C；B研究同时供问题2、3使用的编码器仍放docs/B。

## 必须保持的约束

- `data/`中的原始附件共享读取，不移动、改写或复制到个人目录。自生成数据写入自己的outputs。
- 共享代码保留一个维护来源：C调用B的数据接口和融合基线，B调用A的证据定位，B/C使用C的评估实现。通过接口或产物复用，不复制代码形成独立版本。
- 跨目录开发是允许的，范围以当前任务为准；成员归属不是额外审批流程。修改共享接口时同步必要调用方与文档。
- 不覆盖赛题原文。个人需求建议与全组已采用方案分开记录，不能将个人想法写成赛题要求。
- 无实现的接口写明待实现，未运行的命令写明未验证；实验结论必须对应实际结果。
- 原有题目、总计划及用户正在编辑的文件，除非任务需要，不改名搬迁。移动前核对调用方和文档链接。

## 按任务执行

### 开发、修改接口或整理目录

先确定唯一实现所属目录和受影响调用方，再做任务必要的修改。新增代码采用项目已有语言、依赖和入口形式，不仅为了目录一致而引入新框架。读取 [references/data-and-interfaces.md](references/data-and-interfaces.md) 核对本项目的数据差异与接口交接要求。

接口交接须说明编号、输入输出字段、张量维度、掩码语义、单位、配置、错误或无效样本处理及最小运行示例。具体函数名以实际实现为准，不强制预设抽象层。

验证与改动相匹配：目录调整检查链接与路径；数据适配检查真实样本；模型修改检查必要的前向、损失或短程训练。无需为普通文档改写运行全部模型。

### 需求分析、创新调研或方法设计

写入对应负责人requirements或research目录。读取 [references/document-workflows.md](references/document-workflows.md) 中相应模板。先说明问题和证据，再提出方案；明确哪些是题目硬约束、哪些是实现约定、哪些仍待验证。

已确定且影响全组的结论同步公共约定；仅在影响任务分配或工期时更新总计划。详细论证保留在个人目录，公共文档通过链接引用。普通分析不自动形成新的审批要求。

### 实验与论文

运行产物放个人outputs，可阅读说明放个人experiments。按 [references/data-and-interfaces.md](references/data-and-interfaces.md) 执行数据划分与指标约束，按 [references/document-workflows.md](references/document-workflows.md) 记录复现信息和写作交付。

各负责人撰写自己模块的方法、公式、配置、图表、结论与局限，A负责合并。没有实验支持时写为计划或假设，不补造数值。Markdown与Word采用一个明确编辑源，只有本次任务要求更新导出版时才重新生成。

## 完成与交付

按当前任务检查，而非每次执行全部项目检查：

1. 文件进入正确目录；没有额外复制原始数据或共享实现。
2. 新增引用、相对链接、调用路径有效；中文以UTF-8保存，没有编码损坏。
3. 接口与调用方一致；需要时记录配置、数据版本及验证结果。
4. 需求建议、候选创新和已证实结论标识清楚。
5. 最终回复给出实际改变、文件链接、完成的验证与尚存限制，不声称未运行的实验已通过。

使用PowerShell向Python传递中文文本时，应明确设置UTF-8或通过可靠的UTF-8文件读写；不要依赖控制台默认编码。编写正文优先使用能保留Unicode的文件编辑工具。
