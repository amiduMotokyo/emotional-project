# 项目结构与协作约定

## 1. 结构判断

采用“按负责人隔离实现、按负责人归档文档、共享原始数据”的结构，适合本项目三人三天的工作方式。它能明确归属，降低同时编辑同一文件的冲突，并保留每个人从需求理解到实验结论的完整记录。

需要避免两类问题：一是每个人复制数据加载、融合和评估代码，导致口径分歧；二是个人需求修改被误认为全组已采用的新要求。因此，共享模块保留唯一维护来源，个人建议与共同约定分开记录。

## 2. 归档位置

| 文件类型 | 位置 | 示例 |
|---|---|---|
| 模块代码 | `<A或B或C>/src/` | `B/src/`中的数据读取实现 |
| 参数配置 | `<负责人>/configs/` | 缺失率、批次大小、随机种子 |
| 运行入口 | `<负责人>/scripts/` | 提取、训练、推理脚本 |
| 自生成特征、权重、缓存、原始日志 | `<负责人>/outputs/` | `A/outputs/`中的问题1特征 |
| 需求理解与调整建议 | `docs/<负责人>/requirements/` | 附件3输入字段差异及处理方案 |
| 创新点、文献与方法比较 | `docs/<负责人>/research/` | 缺失鲁棒策略的候选方案 |
| 实验记录、结果分析 | `docs/<负责人>/experiments/` | 基线对比与消融结论 |
| 各自论文正文 | `docs/<负责人>/paper/` | 方法、公式、实验、局限 |
| 论文合并稿 | `docs/A/paper/` | A统稿产生的总稿 |
| 最终提交包 | `C/outputs/submission/` | 代码、结果及必要模型材料 |
| 全组规范与总计划 | `docs/`根目录 | 本文与现有三天计划 |

每个文件保留一个编辑源。若导出Word或PDF，标明对应源文件，修改后再导出，避免多个版本分别编辑。

## 3. 模块边界与交接

| 模块 | 唯一实现归属 | 使用者 | 交接内容 |
|---|---|---|---|
| M1数据读取与统一输入 | B/src/ | B、C | 字段、形状、掩码、文本编码方式、样本编号 |
| M2问题1特征处理 | A/src/ | A | 100条输出、有效长度、处理配置、日志 |
| M3时间映射与证据定位 | A/src/ | A、B | 编号、特征位置、时间单位、时间区间及帧定位 |
| M4融合基线 | B/src/ | B、C | 模型输入输出、配置接口、保存与加载方式 |
| M5缺失模拟与鲁棒训练 | C/src/ | C | 有效区间、缺失位置、类型、时长、随机种子 |
| M6模态贡献与局部解释 | B/src/ | B | 模态贡献、重要位置、解释方法及核查结果 |
| M7统一评估 | C/src/ | B、C | 标签映射、分类与回归指标、F1平均方式 |

截至第二题集成提交，B/src/data.py 与 B/src/fusion.py 已实现附件2对齐版 train/valid、附件3对齐版输入以及共享融合模型；C/src/missingness.py、metrics.py、training.py 已实现第二题连续缺失、训练和统一评估。附件4读取与M6局部解释、A的M2/M3仍未接入。各实现状态以对应README和实验记录为准，不得把计划接口当作已实现功能。

代码通过模块导入复用，运行产物通过明确路径交接。B负责基础模型，C在自己的模块中实现缺失策略；必要的共享接口调整在其原归属目录完成。

## 4. 需求与创新记录规则

1. 各自的新需求理解、调整建议和创新想法写入自己的文档目录，不覆盖赛题原文。
2. 需求文档注明：对应题目条款、当前理解、建议变更、理由、受影响模块、当前状态。
3. 创新调研注明：问题、候选方法、来源、相对基线的区别、实现成本、实验验证方式；实验前标记为假设。
4. 影响全组的已确定结论同步到本文件或总计划；详细论证仍保留在个人目录，通过相对链接引用。
5. 推荐文件名为 `YYYY-MM-DD_主题.md`，持续维护的规范可使用固定名称；不强制每次修订新建文件。

## 5. 已确定的技术与数据约束

- 现有原始数据路径保持不变；各组读取同一份data，不在个人目录复制原始数据。
- 问题1生成的特征存放在A/outputs，问题2、3仍遵循附件2既定划分。
- 训练、验证和对应专项推理使用一致的特征版本。对齐版是当前优先方案，最终选择和编码器配置应在实现后记录。
- 附件3对齐版没有预计算text，应优先解决text_bert编码接口兼容问题。
- 序列位置不直接等于视频秒数；证据映射应说明精度与限制。
- 分类标签映射为0负向、1中性、2正向；实验明确F1平均方式。
- 具体编码器、公共函数签名和最终超参数尚未确定，由相关负责人落实后更新文档。

- 新增项目导航、协作规则和个人目录说明。
- 现有题目、三天计划的Markdown与Word保留原位置，避免影响当前编辑链接。
- 原始data及Office临时锁文件不做修改。
- 当前项目中未发现已交接的问题1代码，后续按A目录约定接入。
